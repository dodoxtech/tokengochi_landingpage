# Copywriting Reference

Used by `landing-page-builder` Step 2 to turn raw, unpolished answers about a landing page section into tight, persuasive copy — without inventing facts, features, or numbers the user never stated.

## Hard rule

Rewrite phrasing and structure only — never add a fact, feature, number, testimonial, or claim the user didn't state. If the raw content is too thin to make a section work (e.g. no differentiator given for the hero), say so and ask the user for more input rather than inventing one. Polishing is compression and clarity, not fabrication.

## Process

### 1. Extract the core idea
For the section's raw input, identify the single most important idea it must communicate. Discard restated points, hedges, and filler — keep every concrete fact (numbers, feature names, proper nouns) intact.

### 2. Apply the right framework for the section

- **Hero** — headline states the core value prop in as few words as possible (verb + benefit + differentiator, no jargon); subheadline expands with the "how"; CTA is a specific action, not "Learn more"
- **Problem / value proposition** — Problem → Agitate → Solve: name the pain point plainly, make its cost concrete, then position the product as the resolution
- **Features / benefits** — lead with the benefit ("so that..."), not the feature name; keep parallel grammatical structure across all items in the list; one idea per bullet
- **Social proof** — lead with the strongest concrete metric or the most specific quote; cut testimonials down to their most quotable sentence
- **Pricing** — plain language, no jargon; make the recommended tier's value obvious without inventing a "recommended" badge if the user never designated one
- **FAQ** — answer-first, no throat-clearing; order questions by what would most likely block a conversion (price, trust, setup effort) first
- **Final CTA** — restate the core value in one line, remove friction from the action phrasing
- **Footer** — functional, not persuasive copy; leave as-is unless genuinely unclear

### 3. Tighten
Cut adjectives that don't add information ("amazing," "revolutionary," "cutting-edge") unless the user's own words specifically used them as brand voice. Prefer concrete over abstract ("saves 3 hours a week" over "boosts productivity"). Keep sentences short enough to scan, not read.

### 4. Present for confirmation
Show the original raw input next to the polished version for each section, with a one-line note on what changed and why (e.g. "led with the benefit instead of the feature name"). Ask the user to confirm, tweak, or reject each one — do not treat polished copy as final until confirmed. If a section couldn't be tightened without inventing information, flag it explicitly and ask a follow-up question instead of guessing.

## Output

The confirmed polished copy per section goes into the brief's "Section-by-section copy" — replacing the raw transcript once the user has confirmed the polished version.
